# Build Log

Twelve days from idea to daily-use tool: August 5 to 16, 2026. 29 commits, 31 GitHub issues (29 closed, 2 open on purpose), built in three working bursts around real rehearsal use. The origin was a one-paragraph idea pasted into a Claude Code session: a tool for making printable play-along chord sheets where the lyrics are always user-supplied and the AI only ever places chord symbols, because asking an AI to lay out a chord sheet directly trips copyright refusals on the lyric text. That constraint became the architecture.

**Aug 5, 11:59 AM. Conventions before code.** First commit is a CLAUDE.md and a design doc, not code. The plan went into GitHub issues as eight phases plus a ninth, "full buildout for other users," filed and immediately deferred. This is a personal tool and the leanest architecture that works was a stated goal, so the product version stayed an issue instead of becoming scope.

**Aug 5, 12:02 to 12:26 PM. Eight phases in 27 minutes.** Scaffold (Vite, React, TypeScript, Vitest), the chord engine (parsing, transposition, key detection, capo as a pure display transform over stored sounding chords), library with localStorage and JSON import/export, the click-and-drag placement editor, the AI round-trip kit (copy a prompt out, paste a reply in, review proposals as accept-or-reject chips), transpose and capo controls, print-first output as literal monospace text rows, and polish. The character-cell layout model from the design doc held through all of it: one monospace grid, chords at column N, print output that can never drift from the editor.

**Aug 5, afternoon. First real paste breaks two assumptions.** Feeding in a found tab surfaced that chord lines were being ingested as lyric text (#10), and that a tab written for capo 4 needs the tool to know that at creation so moving the capo later does not silently rewrite the song (#11). The written-for-capo concept came out of that: symbols in the paste are read as shapes at the stated fret while the header carries the true sounding key.

**Aug 5, evening. Play-along features in the same sitting.** BPM-based auto-scroll (#12), a denser two-column print for short-line songs (#13), SVG chord diagrams on screen and in print (#14), normalized section spacing (#15), hover diagrams (#16), inline lyric editing with line insert and delete (#17), and song notes (#18). Idea to shipped inside one day.

**Aug 6. Persistence meets the real world.** Songs lived only in localStorage until the obvious question: where are my files? Save-the-library-to-folder landed via the File System Access API (#19), and then reality bit again: Brave disables that API by default. The response was both a Brave-specific guidance path and a universal single-file backup that works in any browser (#20).

**Aug 6. The data-integrity wave.** Page-number artifacts from pasted tabs were being stored and printed, so they got stripped at paste, on load, and across the whole existing library (#21). Chords needed to be placeable past line ends and on empty lines for between-phrase progressions (#23). The big one: some imported chord rows were stuck as lyric text, invisible to transpose and capo. The fix was not just repairing one song but a bar-notation-aware parser and an audit pass across every song in the library (#24), followed by a cleanup of the misalignment fallout that repair exposed.

**Aug 6. An idea captured, not built.** A timeline view for dragging song sections into new arrangements got written down as issue #22 with the note "just capture the idea for now, not sure on it yet." It is still open, on purpose.

**Aug 11. Library ergonomics.** Search, persisted sorting with alphabetical default (#25), and setlists: grouped, ordered songs with set navigation for a music set, riding along in folder sync and backup (#26).

**Aug 16. The notation session, including a design reversal.** Diamond hold chords for full-measure holds went through editor, print, export, and the AI format (#27). Section dynamics marks (tacet, soft, build, full, custom) shipped first with tinted section backgrounds (#28) and were overruled the same hour: too busy on a music stand. The replacement is quieter and better: tag pills and a print sidebar with a thin edge bar, and tacet sections shrink to about two thirds size so they tighten up and get out of the way while staying followable (#29). Section tags then unified with free-text overrides (#30), and a migration scan that missed inline-note labels got caught by eye and fixed across all files (#31).

**Since then.** The commit log stops on Aug 16 but the songs folder keeps changing, which is the point: the library is in weekly use for real sets. Known limits, stated plainly: the repo is private because the songs folder contains copyrighted lyrics, voicings for unusual chords fall back to nearest reasonable shapes, and the multi-user buildout (#9) and arrangement timeline (#22) remain deliberately unbuilt.
